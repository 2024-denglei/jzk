# 结构收敛计划

一份有生命周期的工作文档：记录这轮结构治理**按什么顺序做、做到哪了**。为什么这样定不写在这里，写在 `docs/adr/`；用词不写在这里，写在 `CONTEXT.md`。全部步骤完成后本文件应当删除，而不是留下来慢慢过期。

## 起因

项目积累了五类结构问题，其中三类已经在实际造成缺陷：

1. **仓库边界错位**：真正的 git 仓库在 `jzk/`，但工作区开在上一层，那里的 `.git` 是个空目录，导致根目录的 `AGENTS.md` 有一份不在版本控制里。
2. **一个概念四套实现**：打分同时存在旧 DataFrame 路径、启发式路径、进程内模型推理、模型微服务四条代码路径，其中后两者各自维护一份网络定义。「画像」有 7 种表示。
3. **分层名字不符实**：`core` 直连数据库；`api` 与 `dialogue`、`db` 与 `dialogue` 之间存在真实的导入环，且用函数内 lazy import 绕过；`models/` 目录里没有一个 `.py`。
4. **文档描述已死的架构**：`docs/` 下的架构图仍在描述零引用的 `dialogue/response_gen.py`，而应用还挂着 `GET /architecture` 把它对外提供。
5. **配置自相矛盾**：PORT、Postgres 端口、打分服务 token 名、数据文件路径各有两处不一致的定义。

## 半径

**全面收敛**：连领域词汇、目录命名、前后端契约生成方式一起重做。明确排除的范围见文末。

| 5 | 打分收敛：删除进程内模型副本 | ⬜ |

第 1 步排在 CI 之前，因为它是唯一「当前就是坏的」问题，且修复方式是删除一个已无语义的开关，风险接近零。第 9 步必须最后做，因为它要描述的是收敛完成后的形态。

### 各步骤的具体动作

**第 3 步 依赖锁**：建 `pyproject.toml` 声明运行时与开发依赖（`pytest`、`PyYAML` 属于后者，目前混在 `requirements.txt` 里），生成 `uv.lock`，CI 与本地都从 lock 安装。torch 需钉到产出检查点的那个精确版本并注明来由——ADR 0001 要求线上离线共用同一检查点，加载它的 torch 版本属于那份契约。

**第 4 步 配置**：原则是**关键配置不给默认值，宁可启动即失败**。PORT 统一 8010（compose、Dockerfile、Vite 代理三处已是 8010）；`MATCH_SCORER_TOKEN` 与 `SCORER_TOKEN` 合并为一个名字；`POSTGRES_PORT` 统一 5433 并删除与 `compose.yml` 重复的 `db/postgres/docker-compose.yml`；`DATA_FILE_PATH` 删除默认值（它指向磁盘上不存在的文件）；修正 `.env` 里指向 5432 而容器实际发布 5433 的 `DATABASE_URL`。

**第 5 步 打分收敛**：删除 `core/preference/v2/` 与 `core/preference/v2_ranker.py`，`core/preference/scoring_client.py` 成为唯一入口。打分服务不可用时需要显式的降级或快速失败策略，不得退回进程内推理。

**第 6 步 解耦**：从 `api/match.py` 抽出 `execute_match` 到编排层；硬过滤 SQL 生成职责从 `core/preference/sql_filter.py` 下沉到 `db`；`core/data_loader.py` 的查询移入 `db/donors_repo.py`；`db/pg.py` 的 `bootstrap_admin` 不再 import `api.auth_utils`；`api/auth.py`、`api/user.py`、`api/admin_auth.py` 中 handler 内的 SQL 收进仓储层。lazy import 不算合规的规避手段。

**第 7 步 改名**：`core`→`domain`、`models`→`backend/checkpoints`、`services/match_scorer`→`backend/jzk/scorer`、`core/matcher.py` 与 `core/ranker.py` 按实际职责改名（它们做的是筛选）、`db/chat_models.py`→契约命名；`dialogue` 按 `CONTEXT.md` 拆成 `chat/`（对话存储与查询）与 `advisor/`（顾问与生成）；顶层散落的 `main.py`、`config.py`、`redis_client.py`、`password_policy.py` 一并收入包内；去掉 `pytest.ini` 的 `pythonpath=.`。

**第 8 步 契约与前端**：引入 `openapi-typescript`，生成产物落在 `frontend/shared/`；CI 校验生成结果与提交一致；前端按 npm workspaces 拆成 `client/`、`admin/`、`shared/`；后端挂载两个 SPA 入口。

## 沿途发现的缺陷

同一个模式反复出现：**镜像里能跑、开发机上能跑，但从声明的源头装就是坏的**。

- 对话灰度开关默认关闭，而 v1 存储已被迁移脚本删除，任何不携带完整 `.env` 的部署一上线对话就 503 且无处回退。`.env.example` 里两个开关正是 `0`。已修（第 1 步）。
- `httpx` 是 `api/match.py` 与 `core/preference/scoring_client.py` 的直接依赖，却从未出现在 `requirements.txt`，靠 Dockerfile 里一条额外 `RUN` 补上；而当前 openai SDK 依赖的已是 `httpx2`，不再顺带装它。已修（`f61a2d2`）。
- `.env` 的 `DATABASE_URL` 指向 `127.0.0.1:5432`，而 postgres 容器实际发布 5433。在 Docker 外跑应用会连不上库。待修（第 4 步）。

## 明确不做的事

- **前端巨型组件拆分**。`BranchingChatPanel.tsx`(843 行)、`DonorsPage.tsx`(716 行)、`FilterPanel.tsx`(479 行) 暂不动。它与后端结构收敛没有依赖关系，混做会让每个改动都又大又难 review；更实际的顾虑是前端测试全是 utility 与 state 单测，没有任何 DOM 或组件测试，拆这类交互组件缺少护栏。
- **打分服务独立镜像**。目前它与主应用共用镜像、只换启动命令，因此背着并不需要的 `pandas`、`psycopg`、`openai`。这是有意的临时状态，理由见 ADR 0001 的「已知偏离」一节。
- **让筛选走打分服务**。见 ADR 0003。

## 已知环境问题

本机 `127.0.0.1:7890` 上的代理处于「在监听但破坏 TLS」的状态：直连 github.com 返回 200，经代理返回 000。而 git 配置里设了 `http.proxy` / `https.proxy` 指向它，于是 `git push`、`gh`、`pip install` 全部失败，且报错信息误导性极强（`gnutls_handshake() failed`、`token is invalid`）。绕过代理即可恢复。这是开发机问题，不在本计划范围内，记在此处避免重复排查。
