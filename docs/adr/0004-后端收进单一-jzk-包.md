# 后端代码收进 `backend/jzk/` 单一包

后端此前在仓库根平铺着 `api`、`core`、`db`、`dialogue`、`models`、`services`、`voice` 七个顶层包，加上 `main.py`、`config.py`、`redis_client.py`、`password_policy.py` 四个散落的模块，靠 `pytest.ini` 的 `pythonpath=.` 才能导入。我们决定把它们全部收进 `backend/jzk/` 一个包，导入统一写成 `from jzk.domain import ...`。

## 为什么不是 `backend/app/`

FastAPI 教程普遍用 `app/` 作为包名，但那是因为教程里只有一个项目、不需要考虑命名冲突。`app` 和 `db`、`models`、`services` 一样过于通用：配合 `pythonpath=.`，你的 `db` 包和任何同名第三方包处在同一命名空间里抢位置，而这类冲突的报错极难读懂。从别的工作目录跑 pytest，或者将来真的把它装成一个包时，`app` 指向谁取决于运气。

`jzk` 是唯一的。路径里出现 `backend/jzk/` 的重复只是视觉上的，导入语句里永远只有 `jzk.`，而那才是每天要读的东西。

## 为什么分 `backend/` 与 `frontend/` 两层

`backend/` 是部署边界而不是包——`pyproject.toml`、依赖锁、`Dockerfile` 放在这一层。这条边界本来就存在（Dockerfile 已经是 node 构建段 + python 运行段两段），只是过去没有在目录上体现。

## 代价

几乎所有 import 语句都要改，因此这一步必须排在 CI 建立之后，不能在没有自动化验证的情况下做。
