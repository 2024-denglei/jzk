# 管理端权限与操作审批实现计划

## 目标

将管理端从“登录后拥有全部能力”调整为两级权限模型：

- 普通管理员（`donor_admin`）可以查看工作台、用户档案、捐精人档案和业务操作记录。
- 普通管理员不能直接修改业务数据，但可以提交单条操作申请并查看自己的申请。
- 超级管理员（`super_admin`）可以直接执行写操作，并独占管理员中心、审批中心和 Excel 导入。
- 所有安全边界由后端强制执行；前端只负责菜单、路由和操作入口的正确展示。

## 第一版范围

### 支持审批的操作

- 新建捐精人档案
- 修改捐精人档案
- 启用或停用捐精人档案
- 强制用户下线
- 停用用户账号
- 恢复用户账号
- 新增管理员账号（超级管理员直接执行）
- 删除/恢复管理员账号（采用停用式软删除，超级管理员直接执行）

### 暂不进入审批流

- Excel 批量导入：仅超级管理员可执行。
- 物理删除：不实现；使用停用/归档保留关联数据和审计链。

## 权限模型

后端定义稳定的能力名称，并由角色映射能力：

- `dashboard:view`
- `users:view`
- `users:control`
- `users:control_request`
- `donors:view`
- `donors:write`
- `donors:write_request`
- `donors:import`
- `donors:audit:view`
- `requests:view_own`
- `requests:review`
- `admins:view`
- `admins:manage`
- `system:cache_refresh`

`super_admin` 拥有全部能力；`donor_admin` 拥有查看、提交操作申请和查看本人申请的能力。

登录响应和 `/api/admin/me` 返回后端计算出的权限列表。前端不得自行从角色推导权限，避免前后端规则漂移。

## 数据模型

新增 `admin.operation_requests`：

- 申请人、操作类型、目标类型和目标标识
- 操作参数、申请时的对象快照、申请理由
- `pending / processing / approved / rejected / cancelled / failed` 状态
- 审批人、审批意见、审批时间、执行时间和执行错误

审批时以条件更新将 `pending` 原子地改为 `processing`，防止重复审批。执行成功后记为 `approved`，失败或数据冲突记为 `failed`。

新增 `admin.admin_account_audit_logs`，记录管理员账号的创建、停用和恢复。管理员删除采用软删除，并禁止删除当前账号或最后一个启用的超级管理员。

## 后端步骤

1. 新增权限常量、角色权限映射、`require_permission` 依赖。
2. 为现有管理端读写、导入、缓存和管理员中心接口标注权限。
3. 新增可重复执行的数据库迁移及申请数据仓库。
4. 新增申请 API：创建、查看本人申请、审批列表、批准、驳回、撤回。
5. 批准后由服务器调用业务数据层执行操作，并刷新捐精人运行时缓存。
6. 对申请目标保存快照；审批时若目标已变化则拒绝覆盖并标记执行失败。
7. 为超级管理员提供管理员账号创建、软删除和恢复接口，并记录独立审计。

## 前端步骤

1. 扩展管理员信息类型，统一提供 `hasPermission` 判断。
2. 按权限过滤桌面和移动端菜单，保护直接 URL，并显示无权限页面。
3. 超级管理员保留现有直接操作；普通管理员的相同入口改为“申请新增 / 申请修改 / 申请停用 / 申请下线”。
4. 增加“我的申请”页面；超级管理员在管理员中心下看到“操作审批”页面。
5. 审批页面显示申请人、目标、原因、操作数据、状态，并提供批准/驳回操作。
6. 将“我的申请”归入管理员中心导航分组，并在管理员列表提供新增、删除和恢复入口。

## 验证

- 后端单元测试覆盖角色权限、接口 403、申请创建、审批执行、拒绝与冲突。
- 前端测试覆盖权限判断、菜单过滤和操作文案。
- 运行 Python 管理端相关测试、前端测试、TypeScript 构建和 lint。
